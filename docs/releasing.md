# Releasing

How a maintainer publishes a release of azt and what to check when it fails.
How to build and check azt locally is in [development.md](development.md).

## What a release publishes

A `vX.Y.Z` tag runs the [release workflow](../.github/workflows/release.yml),
which runs goreleaser with [.goreleaser.yaml](../.goreleaser.yaml). It
publishes:

- archives for Linux, macOS, Windows and FreeBSD, on amd64 and ARM, each with
  an SBOM;
- `.deb` and `.rpm` packages;
- the Homebrew cask in
  [ingvarch/homebrew-tap](https://github.com/ingvarch/homebrew-tap);
- `checksums.txt` with a keyless cosign signature, and `THIRD_PARTY_NOTICES`;
- macOS binaries signed and notarized by Apple;
- release notes generated by GitHub.

A tag with a suffix, such as `v0.4.0-rc.1`, publishes a prerelease and leaves
the Homebrew cask as it is.

## Before a release

- The repository is public. The workflow refuses to release a private one:
  keyless signing publishes the workflow identity, and brew cannot download
  private assets.
- CI is green on `main`.
- `make dist` passes locally. It builds every platform and package the way the
  release does and publishes nothing.

## Release

```sh
git checkout main && git pull
git tag v0.4.0
git push origin v0.4.0
```

When the workflow finishes, close the version's milestone.

## Secrets

| Secret | What it is |
| --- | --- |
| `HOMEBREW_TAP_GITHUB_TOKEN` | a token that can push to `ingvarch/homebrew-tap` |
| `MACOS_SIGN_P12` | the Developer ID Application certificate, a base64 `.p12` |
| `MACOS_SIGN_PASSWORD` | the password of that `.p12` |
| `MACOS_NOTARY_ISSUER_ID` | the issuer ID of the App Store Connect API key |
| `MACOS_NOTARY_KEY_ID` | the ID of that key |
| `MACOS_NOTARY_KEY` | the key itself, the `.p8` |

`GITHUB_TOKEN` comes from Actions.

## When a release fails

- On signing macOS binaries: run `gh secret list` and look for a missing
  secret first. An empty `MACOS_SIGN_PASSWORD` fails with
  `need password to decode file`.
- The Developer ID certificate expires on 2027-02-01. Before that date, create
  a new one and update `MACOS_SIGN_P12` and `MACOS_SIGN_PASSWORD`.
- On the before hook: a module azt links has a license outside the list in
  `internal/licenses`. `make licenses` shows which one.
